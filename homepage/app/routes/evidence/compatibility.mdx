# Compatibility

"Shiki-compatible" is checked, not claimed. Ferriki tracks one approved Shiki
release at a time, currently **Shiki v4.4.3**.

## How it is checked

- **A pinned mirror of Shiki.** Shiki's own tests run unchanged against
  Ferriki's native engine from an immutable mirror in the repository. Every
  mirrored file is recorded with its SHA-256 digest and verified before and
  after a test run; Ferriki-specific glue lives outside the mirror.
- **A pinned vscode-textmate oracle.** The tokenizer is a mechanical port of
  vscode-textmate v9.3.2, checked against vscode-textmate's own test cases.
- **Explicit exclusions.** Upstream tests outside Ferriki's scope are listed in
  a machine-checked manifest, each with its reason and owning issue.

The Node compatibility gate covers the standard catalogs, language aliases,
themes, HTML output, lazily embedded grammars, injections, custom registrations,
multi-theme HTML, and the supported public exports. The Rust tokenizer and
token APIs remain available to Rust consumers and are checked in the Rust
compatibility suite.

## Native Markdown highlighting acceptance examples

The homepage production build compiles these fences through Ardo's native
Markdown path. They are the fixed corpus for reviewing TypeScript, TSX,
embedded HTML, unknown-language fallback, themes, and code metadata.

```ts title="src/add.ts" [typescript] {2} showLineNumbers
export function add(left: number, right: number) {
  return left + right;
}
```

```tsx title="src/Button.tsx" [tsx] {3} showLineNumbers
type ButtonProps = { label: string };
export function Button({ label }: ButtonProps) {
  return <button type="button">{label}</button>;
}
```

```html title="public/widget.html" [embedded] {3,7} showLineNumbers

    color: rebeccapurple;

<script>
  document.querySelector(".notice")?.classList.add("ready");
</script>
```
