# Class-based output

Nested scope classes make simple styling a few lines of CSS while keeping
ancestor context, scope order, and repeated scopes available for precise rules.
This feature is in the current repository build and ships in the next release.
Inline styles remain the default.

## Use your own CSS

```ts
import { codeToHtml } from "@ferriki/core";

const html = await codeToHtml('const message = "hello";', {
  lang: "javascript",
  theme: "none",
  styleMode: "classes",
});
```

```css
.ferriki .tok-string {
  color: #0a3069;
}
.ferriki .tok-keyword,
.ferriki .tok-storage {
  color: #cf222e;
}
.ferriki .tok-comment {
  color: #57606a;
  font-style: italic;
}
```

`tok-*` classes include every scope prefix in a token's path. `leaf-*` classes
identify its innermost scope. Nested `scope-*` wrappers preserve context:

```css
.ferriki .scope-meta-structure-dictionary-json .leaf-string-quoted-double-json {
  color: #8250df;
}
```

Dots become hyphens, and literal hyphens become `_2d_`. For example, a JSON
property name has `.tok-support-type-property_2d_name-json`. `exact-*` wrappers
identify complete scope names when you need child combinators for exact order
or repetition. Names come from the grammar and can vary between languages.

## Keep your existing themes

TextMate/Shiki themes need no changes. Ferriki resolves their context and
priority rules, then moves the resulting styles into generated CSS classes:

```ts
import { codeToHtmlWithCss } from "@ferriki/core";

const { html, css } = await codeToHtmlWithCss('{"message":"hello"}', {
  lang: "json",
  theme: "monokai",
});
```

Add `html` to the page and `css` to your stylesheet. Combine the CSS from every
rendered block; it covers those blocks, rather than arbitrary future code.
Generated style class names are internal. Use readable scope classes for your
own rules: generated declarations have zero specificity and are easy to override.

Monokai colors a standalone JSON `"hello"` differently from a string inside a
dictionary. The example above retains that distinction. Enable the override to
apply `.tok-string` to both contexts.

## Switch themes with CSS

```ts
const { html, css } = await codeToHtmlWithCss(source, {
  lang: "typescript",
  themes: { light: "github-light", dark: "monokai" },
});
```

Set `data-ferriki-theme="dark"` on the code block or an ancestor. Switch to
`light` to switch back. The generated CSS includes both palettes: the browser
loads no theme JSON and does not tokenize again. A root attribute takes
precedence over an ancestor. `defaultColor: "light-dark()"` follows the system
preference until you select a theme explicitly.

For custom CSS themes, use `theme: "none"` and your site's normal classes,
attributes, or media queries. There is no theme format to adopt.

## Integration details

Classes mode uses a `.ferriki` root instead of `.shiki` and preserves grammar
boundaries, so whitespace and equal-style token merging are skipped.
Transformers and decorations still run; callbacks operate
on source tokens before scopes are nested and styles are extracted. Inline
structure uses a `code.ferriki` wrapper. Transformers that assume the default
flat HTML may need adaptation.

See the [complete class guide](https://github.com/sebastian-software/ferriki/blob/main/docs/class-highlighting.md)
for the class contract, CSS collection, custom variable prefixes, grammar-state
continuation, and the Rust API. The
[experiment report](https://github.com/sebastian-software/ferriki/blob/main/docs/experiments/class-highlighting.md)
records the tested corpus and limits of the coverage evidence.
